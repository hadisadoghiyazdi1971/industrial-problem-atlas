# Industrial Problem Atlas | اطلس مسائل صنعت و جامعه

**A public, problem-first, evidence-driven engineering and scientific initiative.**

اطلس مسائل صنعت و جامعه مجموعه‌ای مستقل از پرونده‌های مسئله‌محور است. هدف، تعریف دقیق مسائل فنی، مقایسه منصفانه روش‌های ساده و پیشرفته، تبیین محدودیت داده‌ها و فراهم کردن بستری برای همکاری دانشگاه، دانشجو و صنعت است.

> **توجه:** هر سه پرونده آغازین «سناریوی پیشنهادی» هستند. هیچ‌یک نتیجه اجرای صنعتی، تأیید سازمان یا بازده اقتصادی اثبات‌شده نیستند. داده آزمایش آموزشی صرفاً مصنوعی است.

## مشاهده سایت

پس از ایجاد مخزن `industrial-problem-atlas` در حساب `hadisadoghiyazdi1971` و فعال‌سازی GitHub Pages:

`https://hadisadoghiyazdi1971.github.io/industrial-problem-atlas/`

انتشار در مخزن، خودبه‌خود به معنی فعال‌شدن Pages نیست؛ راهنمای زیر را دنبال کنید.

## فقط برای شروع: ویندوز

1. محتوای ZIP را در **یک پوشه خالی** استخراج کنید. فایل‌های `index.html` و `PUSH_TO_GITHUB.cmd` باید در همان ریشه پوشه باشند، نه در پوشه داخلی دیگری.
2. برای دیدن سایت روی رایانه، روی `RUN_LOCAL.cmd` دوبار کلیک کنید. این کار به Python 3 نیاز دارد و سایت را روی `http://127.0.0.1:8000` نمایش می‌دهد.
3. برای آزمون آموزشی روی داده کاملاً مصنوعی، روی `RUN_DEMO.cmd` دوبار کلیک کنید. خروجی در `pilot/output/` ساخته می‌شود و در مخزن منتشر نمی‌شود.
4. در GitHub یک مخزن **Public و کاملاً خالی** با نام `industrial-problem-atlas` بسازید (بدون README، gitignore یا license اولیه).
5. اگر Git روی ویندوز نصب است، روی `PUSH_TO_GITHUB.cmd` دوبار کلیک کنید. Git در اولین ارسال ممکن است ورود به GitHub را از مرورگر درخواست کند. اطلاعات ورود را فقط در صفحه رسمی GitHub وارد کنید، نه در اسکریپت.
6. در مخزن GitHub: **Settings → Pages → Build and deployment → Deploy from a branch** را انتخاب کنید؛ Branch=`main`، Folder=`/(root)`، سپس **Save**.
7. پس از آماده‌شدن انتشار، نشانی بالای همین فایل را باز کنید. سایت روی GitHub Pages به هیچ سرویس هوش مصنوعی یا توکن API احتیاج ندارد.

**بدون Git:** مخزن خالی را باز کنید و با `Add file → Upload files` محتوای استخراج‌شده (نه فایل ZIP) را آپلود و Commit کنید. برای ساختار پوشه‌ای پروژه، استفاده از Git یا GitHub Desktop مطمئن‌تر است.

## ساختار

```text
index.html / problem.html / students.html / organizations.html / methodology.html
assets/                 # طراحی و JavaScript بدون کتابخانه جانبی
data/problems.json      # سه پرونده عمومی و وضعیت شواهد آن‌ها
pilot/synthetic_sensor_demo.py  # مثال آموزشی، بدون داده واقعی
pilot/output/           # خروجی محلی، عمداً در git نادیده گرفته می‌شود
handbook/               # پروتکل شواهد، راهنمای دانشجو و تعامل سازمانی
tools/validate_atlas.py # کنترل خودکار صحت داده‌ها و فایل‌ها
.github/workflows/      # آزمون در هر push
RUN_LOCAL.cmd / RUN_DEMO.cmd / PUSH_TO_GITHUB.cmd
```

## اصول علمی

- مسئله و تصمیم واقعی مقدم بر انتخاب الگوریتم هستند.
- روش ساده و خط مبنا باید پیش از مدل پیچیده بررسی شوند.
- نتیجه باید به هزینه خطا، محدودیت عملی و قابلیت اجرا مرتبط باشد.
- اعتبار هر ادعا از «فرضیه» تا «آزمون مستقل» جداگانه درج می‌شود.
- اطلاعات محرمانه سازمان‌ها در مخزن عمومی ثبت نمی‌شود.
- محتوای آموزشی و خروجی مدل‌های مولد باید راستی‌آزمایی شوند.

برای طرح موضوع در شورای صنفی، متن اولیه `handbook/COUNCIL_NOTE_FA.md` را نیز ببینید.

برای افزودن پرونده جدید، قالب `handbook/CASE_TEMPLATE_FA.md` و راهنمای `handbook/EVIDENCE_PROTOCOL_FA.md` را بخوانید. سپس ورودی جدیدی با شناسه یکتا به `data/problems.json` اضافه کنید و این فرمان را اجرا کنید:

```bash
python tools/validate_atlas.py
```

## ارتباط و مسئولیت

این یک ابتکار علمی و آموزشی مستقل است، نه نمایندگی رسمی دانشگاه یا تأیید یک کارخانه. معرفی و نشانی تماس عمومی در صفحه «برای سازمان‌ها» درج شده است. هیچ قراردادی با ارسال درخواست ایجاد نمی‌شود. داده شخصی یا محرمانه نفرستید.

## حقوق استفاده

حقوق تمام محتوای اختصاصی و کد متعلق به صاحبان حقوق مربوطه است. در نسخه آغازین، مجوز استفاده مجدد عمومی تعیین نشده است؛ انتشار عمومی به معنای واگذاری مجوز تجاری یا حق استفاده مجدد از محتوا نیست. درباره امکان مشارکت و بازنشر، پیشاپیش مکاتبه کنید. این متن جایگزین بررسی حقوقی نیست.
